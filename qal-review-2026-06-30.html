QAL 项目周会梳理

会议记录：2026年6月30日。只整理材料中的事实、风险和可验证突破。

总览

本期明确进展

客服 Copilot 一期范围基本定下，计划下周出可测试版本。

科目四 MVT 初版已做完，并完成联调演示。

预定 Agent 反应时长从 80 秒优化到约 20 秒，快筛平均约 4.3 秒。

本期主要风险

多模型切换缺稳定评测体系。

基础质检和 UPS 归因仍受规则、成本和效果影响。

小微接入能调通，但推荐逻辑被指出不适合 AI 预定。

本期明确突破

科目四已能从历史工单生成剧本并进入训练流程。

微信小微接入已调通核心交互，可用开发版体验。

预定 Agent 时延有明显下降。

需要追问

UPS 归因优化后第一版效果是否改善。

科目四软性话术评分何时接入质检标准。

小微项目第一期到底只验证接入，还是验证真实使用。

基础质检 / 深度质检

质量体系

主要发言人：任天、崔宸、陈刚、马田、叶海峰

本期进展

人工复盘场景被重新归并为三类：每单复盘、抽检复盘、服务力质检。

基础执行和风险控制会合到当单总结里，关单时识别服务红线、预约回访、升级主管等问题。

会议中明确命名：一个叫基础质检，一个叫深度质检。

基础质检后续由崔宸主要负责；深度质检会引入夏浩峰经验；人维度质检由蒋缇负责。

风险

模型成本差异很大。Claude Opus 和 GLM 可到十几、二十元一单，DeepSeek v4 约 0.7 元一单。

便宜模型效果还没有验证。

多模型长期使用基本不可避免，但自动化评测还没有接到各项目。

如果全量质检一单超过 1 元，会上升为不可复用的成本问题。

突破

项目边界被拆清楚：基础质检、深度质检、服务力质检。

这是结构进展，不是效果突破。

突破

员工培训承接

从历史工单生成剧本，并进入训练流程，已经跑通初版。

操作类标准答案已做掉。软性话术部分还未完成。

模型评测与切换

AI 客服基建

主要发言人：陶俊杰、吴昊、任天、张志均、王植萌、陈刚

本期进展

途家已开发 Eval 工具，用业务金标数据集横向评测模型。

示例中用 726 条产品标注数据比较多个模型。

支持分类、信息抽取、生成摘要、图片问答等任务，并可按准确率、速度、稳定性、成本综合打分。

商务智能助手通过模型切换已降低一半成本。

风险

金标数据集需要按单个项目或单个需求点建设，前期标注成本不低。

项目指标如何接入评测集还不清楚。

目前更偏项目切换工具，还没有并入公司公共模型接入层。

突破

已有可展示的模型评测工具。

已有项目证明模型切换能降成本。

但在 QAL 项目中还未落地。

Agent 预定

AppAgent / 快筛

端内酒店预定

主要发言人：张中正、陈刚、任天、吴昊、罗征、任紫涵

本期进展

预定 Agent 时长从 80 秒优化到 20 秒，相对稳定。

6 月 30 日发了灰测版本给运营试用，但因版本未完成，当天还会撤回。

快筛依赖月版，暂不能发灰度体验，当前以测试环境视频展示。

快筛 Agent 平均约 4.3 秒反应完，使用 v4 Flash，并关闭思考。

筛选 tab 每天约 30 万 UV；快筛高峰约 100 万到 110 万。

风险

4.3 秒仍被认为偏慢，目标倾向 2 秒左右。

调用链路、网络和模型厂商高低峰都会影响时长。

输入框和语音入口的默认形态还在讨论。

未命中条件、查询无结果、输入参数不支持三类情况需要拆开处理。

突破

从 80 秒降到 20 秒，是明确时延改善。

快筛场景平均 4.3 秒可完成一次响应，但还未达到理想体验。

小微项目

微信小微接入

主要发言人：王现永、陈刚、罗征、吴昊、任天、马田

本期进展

已和携程沟通多次，目标是对齐携程最新交互体验。

计划开发 5 个主流程卡片，包括登录和 LDBO，以及 3 个详情配置。

微信 Agent 主要交互核心流程已调通，前端完成部分酒店卡片。

可通过开发二维码进入小程序内测版，和小微交互并体验预定流程。

下周计划完成前端全部页面开发，7 月 10 日左右前后端全部开发完成。

风险

当前演示不是微信大入口的小微，而是小程序内部调试入口。

能调通接入，不代表能被微信小微稳定召回。

演示中“去北京”直接推荐两个酒店，被指出搜索范围过大，推荐逻辑不成立。

项目第一期被收窄为“能被召回、流程走通”。产品价值暂时不应期待太高。

突破

微信 Agent 核心交互已调通，可用开发版体验。

但业务突破未证明，当前主要是接入能力。

战略地图 Agent

战略地图 / 数据分析 Agent

材料归类

主要发言人：张伊、任天、叶海峰、陈刚

本期进展

原本计划本周演示，但复盘后发现分析结论输出不稳。

问题定位到按需取数没有真正发生。系统实际用一个 SQL 把所有数据跑下来，再塞进 prompt 让 skill 归因。

结论改为先固化几个场景，例如 CPO 或翻译。

后续按徐东模板反向定义 skill 和输出结果，用工程化工作流约束，不让模型自由发挥。

风险

当前分析结论不稳，不能演示。

上下文过长导致输出不稳。

如果数据源不支持下钻到三级，分析深度会受限。

突破

未看到明确突破。

本期主要是发现架构问题，并决定收敛到固定场景。
