行业观察

旅行 Agent 不是 OTA 的终局

OTA 的消费者界面已经接近稳定终局。AI 真正改变的，是后台的成本与履约，不是用户为什么打开 OTA——这是经过现实检验之后的判断。

先看今天 OTA 的核心页面：

输入目的地和日期 → 展示几百家酒店 → 筛选排序 → 用户选择。

下一代可能变成：

用户说需求 → AI 理解约束 → 生成方案 → 自动组合采购 → 行中调整 → 售后处理。


用户不再"使用 Booking 搜酒店"，而是把一次旅行目标交给它。

这个判断听起来顺理成章。但现实检验之后，我发现它只对了一半。

第一版判断：OTA 会变成 AI 驱动的交易与履约网络

一句话概括：前台从货架变成 Agent，后台从信息撮合变成交易基础设施。核心逻辑是五条：


1. 货架式搜索最先消失。OTA 辛苦积累二十年的"搜索与排序产品"，会被压缩到一次 Agent 调用里——搜索框、筛选器、列表页从主入口退化为辅助工具。

2. 平台真正的下一步是"旅行执行 Agent"。订单不再是一次交易，而是持续十几天甚至几个月的任务；Booking 的 Connected Trip 会从交叉销售逻辑，升级成持续执行逻辑。

3. 前台可能被别人拿走，后台反而更加重要。ChatGPT、Google、抖音都可能截走用户入口，但库存、价格、支付和售后仍要经过 OTA——平台从显性的流量品牌，变成隐性的交易基础设施。界面可能被去中介化，履约却很难被去中介化。


未来会发生这样的分层：

层次 谁可能掌握 核心价值
用户入口 ChatGPT、Google、抖音、OTA Agent 理解用户、生成方案
决策与编排 旅行 Agent 跨品类组合、动态决策
交易网络 Booking、Expedia、航旅平台 库存、价格、预订、支付
履约与风险 OTA、供应商、保险机构 改签、退款、兜底、赔付
实际供给 酒店、航司、景区 提供服务

4. 护城河会改变。从流量、酒店数量和评论，变成可执行的供给网络、跨供应商履约能力、支付与信用、真实结果数据——静态信息很容易被 AI 获取，可靠执行权很难复制。

5. 商业模式会从流量抽佣变成多层收费，行业也不会是一家吃掉全部。更可能拆成三类：拥有用户的旅行 Agent、拥有交易网络的平台、拥有独特供给的经营者。OTA 最大的风险，是失去上层的用户决策权，只剩下层的交易履约权。


对去哪儿的启示：不能只做"能聊天、能推荐"的助手，那层能力很快会成为标配；真正该建设的是用户 Agent、交易编排系统、履约网络三层——把低价升级成 Agent 能够理解和执行的结构化低价。

最后我的核心判断是：

OTA 1.0卖库存，OTA 2.0卖比较和流量，OTA 3.0卖完整交易，下一代平台卖的是"替用户承担一次旅行的决策与履约责任"。

谁只是生成答案，谁就会成为薄薄的一层功能；谁能够可靠地执行、修改并为结果负责，谁才是下一代平台。

但做了这么久，我发现现实并非如此

好像做了这么久，并非如此。

比如行程规划，我们实际生活中的行程规划基本不是靠理性推荐，而是自己去看非常多的视频和图文，形成兴趣。

再比如订酒店，在 LLM 里订酒店并没有特别的价值：没有 OTA 的基础信息，LLM 无法完成自然语言搜索；反过来说，OTA 也能做相同的事情。

更麻烦的是，多数人订酒店没有那么复杂，几个条件就可以选择了，更多的是选择地段和价格。

LLM 没有足够的用户价值，让用户改变预订习惯。

再往前推一步：修正后的判断

对。再往前推一步，你这个观察实际否定了一个流行前提：

旅游不是"信息不足、决策复杂，所以需要 AI 代替决策"的行业。

很多时候，浏览、比较、想象本身就是消费体验；最后的交易反而很简单。


所以不能因为大模型出现，就倒推出 Booking、Expedia 下一步必然是"旅行 Agent"。

更可能的答案是：OTA 的消费者产品已经相当接近稳定形态，未来主要不是产品形态革命，而是平台经营深化。

一、行程规划本来就不是一个标准优化问题

AI行程规划假设用户的需求是：我有一组明确偏好，请替我求出最优旅行方案。

但现实更像：我还不知道自己想去哪儿，通过不断看内容，逐渐形成兴趣。


这个过程有几个特点：

偏好不是预先存在的，而是在浏览中生成；用户喜欢偶然发现，而不是只看"最适合自己"的结果；图片和视频提供的是氛围感，文字总结无法替代；用户经常不是在完成任务，而是在消遣和想象；决策过程可能持续几周，并不追求效率最大化。


所以"看了100条视频才决定去北海道"，不能被视为低效率。那100条视频本身就是旅行体验的前半段。

LLM可以总结"北海道适合什么人"，却很难制造某个雪景视频带来的欲望。

旅游首先是欲望生成，之后才是理性选择。

二、酒店预订已经被OTA压缩得足够简单

大多数酒店预订实际上是一个非常浅的决策漏斗：

去哪里；住哪个地段；大约多少钱；评分是否过关；看图片和差评；下单。

OTA现有的地图、价格、评分和筛选器，已经非常适合这个任务。


假设用户说：

帮我找东京交通方便、安静、适合带父母、每晚1500元以内的酒店。

LLM表面上理解了需求，但真正产生结果仍然依赖OTA拥有的数据：

用户表达 实际需要的底层数据
交通方便 酒店坐标、地铁站、线路和距离
安静 房型、临街情况、评论语义
适合父母 电梯、步行坡度、房间面积、早餐
1500元以内 实时库存、税费和汇率
值得住 评分、差评、价格和取消政策

LLM没有这些数据，就只能说一些看似合理但无法交易的话。

OTA有了这些数据，接一个通用模型便能做同样的自然语言解析。

因此：大模型不掌握供给，OTA又不缺大模型。

自然语言酒店搜索很难成为ChatGPT相对OTA的结构性优势。

三、自然语言也没有明显战胜现有界面

对简单、明确、频繁修改的条件，点击往往比对话高效。

用户通过地图一眼就能看见：酒店在哪儿；周围有什么；贵多少；还有哪些选择；改一下价格区间会发生什么。

而对话界面每次只展示少量答案，会损失空间关系、价格分布和选择控制感。


尤其旅游属于低频、高金额、容易后悔的消费。用户通常不愿意只接受Agent给出的三个答案，而是仍想确认：

有没有漏掉更便宜的；隔壁街区怎么样；为什么不推荐这一家；这张照片真实吗。


所以合理形态不是"对话替代列表"，而是：

AI帮助用户设置条件、解释差异，地图和列表继续承担最终选择。

这只是搜索体验的一项改进，不足以改变预订习惯。

四、过去几年旅行规划产品没有起飞，不只是技术不够

如果问题只是模型能力不足，那么随着模型进步，用户使用应该明显增加。但旅行规划类产品长期面临的是更基础的问题：


使用频率太低：多数用户一年只有几次复杂旅行，没有动力学习和养成一个新的Agent入口。

错误成本太高：餐厅推荐错了损失有限，酒店日期、位置、房型、签证或者退改规则错了，损失可能很大。

结果难以验证：Agent声称这是"最适合你的酒店"，用户无法确定它搜索了多少库存、是否受佣金影响、有没有漏掉促销。

交易仍需人工确认：只要用户还要核对日期、价格、房型、行李和取消政策，Agent节省的操作就很有限。

选择本身具有愉悦感：不少人愿意花时间看酒店、攻略和视频，并不希望被完全自动化。


所以旅行Agent没有大规模普及，并非再等一次模型升级就会自然解决，而是消费者价值本身可能没有想象中大。

五、由此得出的重要结论：OTA可能已经接近消费者产品的"稳定终局"

Booking、Expedia并不一定需要变成一个全新的物种。

类似超市、电商、搜索引擎，基本交互可以保持二十年：搜索—筛选—比较—购买。

它们下一步更像经营进化，而不是界面革命：


1. 从单次交易转向会员经营

用会员价、积分、跨品类权益和售后保障，降低用户每次重新比价的意愿。

本质是把"哪里便宜就去哪里买"变成"差不多就继续在这个平台买"。


2. 从酒店佣金扩展到旅游零售利润

增加：机票、租车、接送和门票；保险和价格保障；支付、汇兑和分期；广告和商家推广；企业差旅和B2B分销。

增长不一定来自新的消费者界面，而来自一位用户、一笔旅行产生更多收入。


3. 从流量平台转向供应链控制

加强：独家价格；会员库存；实时确认；支付结算；商家运营工具；退款与赔付能力。

消费者仍然看到相似的酒店列表，但平台对交易的控制更深。


4. 从B2C品牌转向旅游基础设施

特别是Expedia，可以把库存、预订、支付和售后提供给银行、航空公司、会员平台以及未来的AI入口。

即使用户从ChatGPT开始，最后调用的仍可能是Expedia的供给。


5. 用AI降低内部成本

AI更确定的价值发生在用户看不见的地方：自动处理退改和航变；客服自动化；评论总结与违规识别；酒店信息维护；商家服务；营销素材生产；软件开发和内部运营。

这会改善利润率，但不会创造一种全新的OTA。

六、真正可能改变OTA的不是LLM，而是"兴趣平台能否闭环交易"

抖音、小红书、YouTube对OTA的威胁比通用LLM更大，因为它们参与了需求形成。

但内容平台也有自己的结构性问题：

从种草到出行可能间隔数月；用户看内容时未必有明确日期和预算；酒店是标准商品，最终仍会跨平台比价；复杂售后与平台内容体验完全不同；交易需要库存、支付、客服和供应商治理。


所以最可能出现的不是内容平台全面取代OTA，而是重新分工：

内容平台制造兴趣并获得广告收入；OTA承接搜索、价格比较、交易与履约。

部分流量入口会迁移，但OTA的交易层仍然稳定。

七、对去哪儿的战略含义也要相应收缩

不应该把"旅行Agent"当成一个新的主航道。它更适合作为若干局部能力。

场景 AI价值 是否改变入口
行程灵感生成 有一点 很难
酒店自然语言搜索 有一点 很难
评论与差评总结 明确 不改变
低价差异解释 明确 不改变
退改、航变和投诉 很高 可能形成服务入口
客服与商家运营 很高 属于后台革命
多人多程复杂出行 较高 小众场景
普通酒店预订 很低 基本不改变

去哪儿真正应该关注的不是"做不做一个旅行Agent"，而是三个更具体的问题：

内容平台种草后，如何让用户更自然地进入去哪儿完成比较；

如何继续强化地段、价格、时间和风险的选择效率；

如何用AI大幅降低交易后的履约成本。

我的修正结论是：

Booking、Expedia下一步未必是"变成什么"，而是继续成为更深、更赚钱、更自动化的OTA。

前台仍然是地图、图片、价格和列表；后台逐渐变成高度自动化的供给、支付、广告和履约系统。

AI在这里大概率是一项类似移动化、云计算和推荐算法的基础技术：会改变成本和局部体验，却未必改变用户为什么打开OTA、怎样挑酒店以及最终为何下单。
